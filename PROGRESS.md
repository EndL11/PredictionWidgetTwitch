# PROGRESS

## Статус
Робоча версія. Протестована в демо-режимі й автотестами (headless Chrome). **З реальним каналом Twitch ще не перевірялась**, це перший пункт беклогу.

## Історія (зроблено)

### v0.1: базовий віджет
- EventSub WebSocket: підписки на `channel.prediction.begin/progress/lock/end`, keepalive, reconnect, revocation.
- Підхоплення активного прогнозу після перезапуску OBS (`GET helix/predictions`).
- Компонування для 2 варіантів (синій/рожевий, таймер посередині, смуга з %) і для 3–10 варіантів (список смуг).
- Звук на старті: вбудований Web Audio або свій файл (`sound`, `volume`, `lock_sound`).
- `setup.html`: інструкція, implicit OAuth, валідація токена, генерація URL.
- Демо-режим `?demo=1`.

### v0.2: результати
- Після розрахунку показуються списки найбільших переможців і програвших (з `top_predictors`).
- Прозорий фон, тінь тексту, темна плашка під кожним ніком.

### v0.3: вигляд як у референсі
- Списки над своєю стороною, пливуть знизу вгору й розчиняються вгорі. Заголовок приглушується під час прокрутки.
- Плашки варіантів: коефіцієнт `1.94x`, бали, `Winner!`.
- Картка притиснута до низу джерела. Рекомендований розмір 660×360.
- Параметри `rows`, `speed`, `results`.

### v0.4: плавність
- DOM перебудовується лише при зміні стану прогнозу. Числа анімуються (tween ~0.9 с, ease-out), смуга теж плавна, у тому числі під час зміни статусу.

### v0.5: показ і приховування
- Віджет ховається через `lock_hide` с після закриття ставок (за таймером або вручну). Якщо подія lock запізнюється, спрацьовує й за власним таймером.
- З'являється знову, коли прогноз розраховано. Ховається через `hide` с після прокрутки списків.
- LOCKED-прогноз при старті OBS не показується.
- Додано `tests/test_lifecycle.py` і `tests/screenshots.py`.

### v0.6: віджет по центру
- Картка стоїть по центру джерела (горизонтально й вертикально), а не в лівому нижньому куті. Джерело на весь екран показує віджет посередині.
- У тест додано перевірки: картка в центрі 1280×720, списки результатів вміщаються над карткою в 680×360.

## Беклог / ідеї
- [ ] **Перевірити на реальному каналі**: прогноз з 2 і з 3+ варіантами, ручне закриття, скасування, перезапуск OBS посеред прогнозу.
- [ ] Звірити семантику `channel_points_won`: чи це повна виплата (ставка + прибуток), чи лише прибуток. Зараз у списку «Виграли» показується значення як є.
- [ ] Обробляти протермінований токен м'якше (показувати попередження за кілька днів до кінця, бо `validate` повертає `expires_in`).
- [ ] Перейти з implicit grant на Device Code Flow або Authorization Code + refresh token, щоб не оновлювати токен вручну кожні ~60 днів (може знадобитися маленький локальний сервер).
- [ ] Окремий звук на результат (`end_sound`).
- [ ] Теми і кастомізація кольорів або шрифтів через параметри (`theme`, `color_a`, `color_b`, `font`).
- [ ] Анімація появи нових рядків для 3+ варіантів і пересортування за балами.
- [ ] Локалізація (EN) для публічного релізу.
- [ ] GitHub Pages: хостити `setup.html`/`widget.html`, щоб посилання для OBS було https, а не `file://`.

## Відомі обмеження
- Twitch дає лише топ-10 учасників на варіант, тому повного списку всіх, хто ставив, немає.
- Implicit-токен живе близько 60 днів, оновлювати треба вручну через `setup.html`.
